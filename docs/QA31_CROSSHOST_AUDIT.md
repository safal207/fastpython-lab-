# AlexPy 3.1 — независимый кроссплатформенный аудит QA Route Matrix

**Статус:** read-only исследование. Без изменения выбора маршрутов в AlexPy, без изменения `main`, без включения по умолчанию.

## Вопрос

Есть ли воспроизводимое доказательство того, что экспериментальный QA 3.0 Route Matrix выбирает более быстрый маршрут, не ухудшая p95, p99 и память, на шести конфигурациях CI? И правильно ли QA 3.0 возвращается к исходному C-дереву при недостаточных доказательствах?

## Зафиксированные источники

* Репозиторий: `safal207/fastpython-lab-`, PR #1, Draft.
* Исходный SHA текущего проверенного CI: `43d5ec6084af0dc5aa12dee0fa6ac36631a9dc75`.
* Два независимых CI-запуска: [45717781984](https://github.com/safal207/fastpython-lab-/actions/runs/45717781984) и [45717790340](https://github.com/safal207/fastpython-lab-/actions/runs/45717790340), оба `success`.
* В каждом запуске: `ubuntu-latest`, `macos-latest`, `windows-latest` × Python 3.13/3.15.
* 12 **скачанных оригинальных** артефактов GitHub Actions `alexpy-qa30-...`, по одному на каждую комбинацию запуска/ОС/Python. Они сохранены побайтово в исследовательском ZIP-пакете, с SHA-256 ZIP и `qa30-results.json` в `evidence/qa31-artifact-manifest.json`.
* `qa30-results.json` содержит исходные семплы 3 независимых обучающих процессов, замеры 4 отложенных нагрузок, наблюдения памяти и стоимость диспетчеризации.

## Протокол независимой проверки

1. Проверка точного имени артефакта, номера GitHub run, полного commit SHA, ОС и версии Python; нельзя смешивать один источник с другим.
2. Полное покрытие 2 запусков × 3 ОС × 2 версий Python, без дубликатов.
3. Не менее трёх различных PID в каждом обучающем наборе; у каждой строки четыре маршрута и одинаковые исходные характеристики нагрузки.
4. Пересчёт медианы, p95 и p99 **по всем сырым временным семплам** (nearest-rank для хвостовых квантилей), пересчёт медианы пика `tracemalloc`.
5. Восстановление исходного консервативного правила QA 3.0 из **только тренировочных** измерений: минимум 5% выигрыша по медиане после измеренного overhead, отсутствие ухудшения p99 и отсутствие увеличения пиковых отслеживаемых аллокаций **в каждом процессе**.
6. Проверка совпадения сохранённых решений с независимо восстановленными. Отложенные нагрузки не участвуют в обучении.
7. На четырёх отложенных нагрузках вычисляются отношения `adaptive / c_tree` отдельно для median, p95, p99 и `tracemalloc`; при значениях выше 1 маршрут хуже контроля.
8. Чёткая граница: автоповышение версии запрещено независимо от результатов этого постфактум-аудита.

| Проверенные GitHub CI-запуски | 2 / 2 successful |
| Архивы CI | 12 |

| Повторно рассчитанные обучающие решения | 36 |
| Отложенные сценарии | 48 |
| Решения `c_tree` | 36 / 36 |
| Другие допустимые маршруты | **0** |
| Медиана отношений adaptive/c_tree по времени | **1,005×** |
| Медиана отношений adaptive/c_tree по p95 | 1,004× |
| Медиана отношений adaptive/c_tree по p99 | 1,000× |
| Медиана отношений adaptive/c_tree по `tracemalloc` | 0,977× |
| p95 > контроля на 5% | 6 / 48 |
| p99 > контроля на 5% | 12 / 48 |
| Наибольшее отношение p99 | 1,679× |

В 12 из 48 отдельных сравнений p99 превышал C-дерево более чем на 5%, но **только одна из 24 сопоставимых конфигураций** повторила этот признак в обоих запусках: macOS, Python 3.13, 29 тестов, пакет 1. Отношения p99: **1,348×** и **1,067×**. Для коротких программ на общих виртуальных CI-раннерах такое расхождение может быть шумом. Оно требует более длинных, заранее зарегистрированных измерений, а не немедленного изменения алгоритма.

Все 12 обучающих матриц независимо воспроизвели решение `c_tree`. Это **успех защитного режима**, но отсутствие доказанного улучшения. `adaptive` на отложенных нагрузках — вызов той же базовой реализации с небольшой дополнительной стоимостью поиска маршрута.

## Доказательства и воспроизведение

В полном исследовательском архиве находится `raw/qa30-<artifact_id>.zip` для каждого GitHub артефакта. Запуск без сети:

```sh
PYTHONPATH=. python -m unittest discover -s tests -p 'test_qa31*.py' -v
PYTHONPATH=. python -m alexpy.qa_crosshost \
  --manifest evidence/qa31-artifact-manifest.json \
  --raw-dir raw \
  --output evidence/qa31-recomputed.json
```

На GitHub достаточно хранить исходный аудитор, тесты, компактный отчёт и SHA-256-манифест; полный набор ZIP-артефактов сохранён также в исследовательском архиве. Нельзя объявлять GitHub Actions-артефакты бессрочными: срок их хранения ограничен.

## Ограничения и решение

* 48 синтетических отложенных нагрузок происходят из уже реализованного QA 3.0; это **не новая внешняя продукционная выборка**.
* Набор из семи наблюдавшихся CI-заданий Roby's в QA 2.9 — исходный формат сценария, а не замеры задержки отдельных браузерных тестов. Масштабированные потоки — синтетические копии.
* Квантили в отчётах измеряют **время полного replay с созданием движка**, а не p99 ожидания реального конечного пользователя.
* Между Ubuntu, macOS и Windows нельзя усреднять абсолютные наносекунды как единый аппаратный профиль. Отношения перечислены отдельно, а общая медиана служит описательной сводкой, не статистическим CI.
* Полученные эффекты времени на общих CI-раннерах не обосновывают вывод о статистической значимости.
* Пиковые `tracemalloc`-аллокации не равны полной RSS; результат нельзя использовать как доказательство меньшей физической памяти.

**Решение:** сохранить QA Route Matrix как opt-in / research. Не изменять базовый C-движок и не включать маршрутизатор автоматически. Следующий фальсифицируемый эксперимент — заранее зафиксировать независимые более длительные workload-следы и провести парные повторы p95/p99 в разных процессах для macOS Python 3.13 и Linux/Windows как отрицательных контролей. В эксперименте обязательно измерять расходы выбора, прогрев, RSS и корректность результата.
